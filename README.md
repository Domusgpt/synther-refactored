# Synther Refactored

A Flutter synthesiser playground that focuses on a clean Dart-first audio
architecture and a polished holographic themed UI. This refactor replaces the
previous native audio bindings with a pure Dart backend so the project can be
built and run on any platform supported by Flutter without additional native
setup.

## Project Highlights

- **Pure Dart audio backend** – deterministic `AudioBackend` implementation with
  stateful voice tracking and simulated LFO modulation metrics for UI
  visualisation.
- **Polyphony-aware voice allocator** – velocity-sensitive voice stealing with
  runtime configurable limits exposed through the bridge and presets.
- **`AudioEngine` façade** – keeps parameter updates (including the new tempo
  transport state) plus preset loads and visualiser data in sync with the UI
  layer.
- **Expressive oscillator & FX controls** – blend/detune/spread the oscillators
  and dial in chorus or drive with alias-aware metadata that syncs across the
  engine, bridge, presets, and visualiser metrics.
- **Granular & sample controls** – enable grains, shape density and motion,
  sweep wavetables, and balance microphone input levels with the same
  registry-driven alias handling used elsewhere in the engine.
- **Performance controllers & expressive ranges** – portamento, pitch bend,
  mod wheel, aftertouch, expression pedal, and sustain pedal values flow
  through the shared registry so presets, the UI, and the visualiser react to
  real-time playing techniques with matching metrics like `performanceEnergy`
  and `sustainActive`.
- **Programmable arpeggiator** – sculpt rhythmic phrases with per-patch
  arpeggiator enable, rate, gate, octave span, direction, pattern, swing,
  latch, tempo-sync, and note division controls that stream through the backend,
  bridge aliases, presets, and visualiser metrics.
- **Tempo transport & sync** – global BPM/play/time-signature metadata exposed
  through the bridge, presets, and visualiser with automatic rate conversion for
  tempo-synchronised arpeggiator divisions and an in-app transport control
  panel for live tweaking.
- **Modulation matrix & analytics** – capture modulation routes (e.g. LFO →
  filter cutoff) inside presets, tweak them live with the modulation matrix
  control panel, and expose aggregated metrics such as `modSource.*`,
  `modDestination.*`, and `modulationEnergy` for the holographic visualiser.
- **Preset library & tooling** – capture current sounds, apply curated factory
  presets, and parse loosely structured preset data generated by AI tools.
- **Holographic UI** – glassmorphism driven controls, animated parameter panels
  (including modulation and transport sheets), and a WebGL visualiser bridge.
- **Cross-platform focus** – runs on mobile, desktop and web using Flutter’s
  rendering and the BasicAudioBackend for predictable behaviour.

## Playability & Distribution

The synth is playable anywhere Flutter runs:

- **Android/iOS** – install debug builds directly on devices with `flutter run`
  or export signed release builds (`flutter build apk`, `flutter build ipa`) for
  distribution through app stores.
- **Web** – enable Flutter web support once (`flutter config --enable-web`), run
  with hot reload in Chrome, or host the static `build/web` output on any web
  server for instant browser-based play.
- **Desktop (Windows/macOS/Linux)** – enable the relevant desktop targets,
  launch with `flutter run -d windows|macos|linux`, or produce release binaries
  for studio rigs and live performances.

See the [Distribution & Playability Guide](documentation/distribution_guide.md)
for detailed command sequences, tooling prerequisites, and hosting tips.

```
lib/
├── core/                # Audio engine, backend contracts and parameter models
├── design_system/       # Glassmorphic widgets and shared UI components
├── features/            # Higher level features (presets, visualiser bridge)

└── utils/               # Support utilities like audio/UI sync helpers
assets/visualizer/       # WebGL visualiser bundle consumed by the app
native/                  # Placeholder for future native backends (optional)
```

## Development Setup

1. Install the **Flutter SDK** (version 3.19 or later recommended) from the
   [official installation guide](https://docs.flutter.dev/get-started/install).
   This installation bundles the Dart SDK.
2. Ensure the Flutter tools are on your `PATH` and run the bundled setup script:

   ```bash
   tool/setup_dev_environment.sh
   ```

   The script validates the presence of `flutter` and `dart`, runs `flutter
   doctor` for sanity checks, and fetches all project dependencies via
   `flutter pub get`.
3. Open the project in your preferred IDE (VS Code or Android Studio) and let it
   discover the Flutter project structure.

### Common Commands

```bash
flutter run            # Launch the application on a connected device or emulator
flutter test           # Execute widget and unit tests
flutter analyze        # Static analysis using Flutter’s linter rules
dart format lib test   # Apply automatic formatting
```

> **Tip:** Add the Flutter extension (VS Code) or the Flutter/ Dart plugins
> (Android Studio/IntelliJ) for rich IDE tooling, code completion and debugging
> helpers.

## Troubleshooting

- `flutter doctor` reports missing platform toolchains – follow the guidance in
  the command output to install Android Studio, Xcode (macOS) or other platform
  SDKs you intend to target.
- Dependency fetch failures – ensure you have an active internet connection and
  that proxy settings allow `pub.dev` access. Running `flutter pub cache repair`
  can also help recover a corrupted cache.
- Web build issues – confirm that you have Chrome or another supported browser
  installed, then run `flutter config --enable-web` if necessary.
